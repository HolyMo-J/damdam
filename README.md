# 담담 (damdam)

토스증권 Open API를 이용한 주식 자동매매 봇 프로젝트입니다.

이름 "담담"은 급락에도 급등에도 흔들리지 않고, 미리 정한 규칙대로 매매한다는 뜻입니다.

## 프로젝트 목표

- 감정적인 매매 대신, 정해둔 규칙대로 손절과 청산을 실행하는 봇을 만든다
- 최종 목표는 국장과 미장을 상시 감시하며 매수 결정까지 봇이 내리는 자동 트레이더다. 결정은 사람과 Claude가 설계하고 고친 규칙 전략을 봇이 그대로 실행하는 방식이고, 봇 안에 LLM API는 연결하지 않는다. 사용자는 언제든 매수와 매도를 정지할 수 있다. 코인은 대상이 아니다
- 부수입 수단이면서, 동시에 백엔드 개발 포트폴리오로 쓴다
- 아래 5단계로 나눠서 점진적으로 완성한다

| 단계 | 내용 |
| --- | --- |
| 1 | 조회와 청산 봇: 매수는 사용자가 직접, 청산(매도)은 봇이 규칙대로 자동 실행 |
| 2 | 과열 급락 반등 전략 백테스트 (구조적 한계로 잠정 보류) |
| 3 | 매수 전략 후보를 실시간 가상매매로 검증 (실제 주문 없이 신호를 찾아 가상으로 사고팔고 기록) |
| 4 | 3단계 판단 기준을 통과한 전략만 소액 실전. 봇이 소액 한도 안에서 사람 승인 없이 스스로 매수와 청산 (국내 종목부터) |
| 5 | 규모와 시장 확장: 한도 상향, 미장 확장 (설계 전) |

## 지금 진행 상황

- **1단계**: 조회, 체결 감지, 시간 청산, ATR 익절/손절 OCO 자동 등록이 구현돼 있고 실전 전환 체크리스트([docs/live-checklist.md](docs/live-checklist.md))까지 준비했습니다. 실전 전환은 아직 하지 않았고 기본값은 모의 실행입니다
- **2단계**: 백테스트는 포트폴리오 게이트를 통과하지 못했고, 완화 시도와 신호 재설계 시도도 표본 부족 등 구조적 한계로 막혀 잠정 보류했습니다
- **서버 이전**: 장중에 계속 켜져 있어야 해서 집 PC 대신 클라우드 서버로 옮기는 작업을 진행 중입니다 ([docs/deploy.md](docs/deploy.md), 가입 절차 대기 중)
- **3단계**: 서버 없이 할 수 있는 코드 구현을 먼저 하고 있습니다. 전략 두 개의 신호 계산, 주문 경로 차단 가드, 대상 종목군 필터, 데이터 조회 연결(신호 판정), 실측 조회 러너까지 끝났고 남은 것은 신호 확정 시점 스케줄과 가상 체결 및 기록입니다. 가동은 서버 이전 뒤입니다

자세한 진행 상황은 [docs/todo.md](docs/todo.md), [docs/done.md](docs/done.md)를 참고하세요.

## 현재 할 수 있는 것

- 토스증권 Open API 인증 토큰 발급, 저장, 재사용
- 계좌 목록, 보유 종목, 평가손익 조회
- 웹소켓으로 실시간 주문 체결 감지, 끊기면 재연결하고 주문 목록으로 재동기화
- 감지된 체결을 `records/manual_trades.csv`에 기록 (계좌 식별값 없음)
- 최대 보유 5거래일(docs/strategy.md v0) 도달 시 시간 청산: 이 기능을 켜기 전부터 갖고 있던 종목은 알림만, 이후에 새로 산 종목은 실제로 시장가 매도 주문까지 자동 실행
- 디스코드 웹훅 알림: 안전장치 발동, OCO 등록 실패, 웹소켓 재연결 실패, 403(허용 IP), 봇 시작과 종료 (웹훅 주소는 `.env`의 `DAMDAM_DISCORD_WEBHOOK_URL`에만 두며, 비워두면 알림 없음)
- 정지 파일: `bot/data/STOP` 파일을 만들면 재시작 없이 자동 매도와 OCO 등록/수정이 즉시 멈춤 (아래 운영 참고)
- 자동 매도는 기본값이 모의 실행이며, 1회 금액 한도, 하루 횟수 한도, 연속 손실 시 정지 같은 안전장치를 거쳐야만 실제로 전송됨 (아래 보안 항목 참고)
- 매수 체결을 감지하면 평단가와 14일 ATR 기준으로 익절/손절 OCO 조건주문을 자동 등록하거나 수정 (자동 매도와 같은 모의 실행 기본값, 실전 전환 시 실제로 전송)
- 백테스트용 과거 일봉 수집, 수수료율 조회, 거래대금 상위 종목 선별
- (3단계, 아직 가동 전) 전 거래일 거래대금 상위 100종목에서 ETF, 우선주, 정리매매, 투자경고와 투자위험, 거래정지 종목을 뺀 가상매매 대상 종목군 계산
- (3단계, 아직 가동 전) 종목마다 일봉과 기관 매매동향을 조회해 전략 A(기관 순매수 추종)와 전략 B(일목 구름대 상향 돌파와 거래량 급증)를 판정. 조회 실패, 데이터 오류, 봉 부족을 "신호 없음"과 구분해 남기고, 조회 장애로 판정하지 못한 전략이 많으면 정상 결과로 돌려주지 않고 예외를 던짐
- (3단계) 가상매매 코드는 조회 API만 쓰고 주문 경로에 닿지 않도록 정적 테스트(`PaperTradingIsolationTest`)로 지킴
- (3단계) 실측 조회 러너: 명세만으로 알 수 없는 값(순위 집계 시각, 일봉과 기관 매매동향의 저녁 확정 시각 등)을 실제 응답으로 확인 (아래 "실측 조회 러너" 참고)

## 기술 스택

| 영역 | 기술 |
| --- | --- |
| 봇 본체 | Java 21, Spring Boot 4.1.1, Gradle |
| API 호출 | Spring RestClient |
| 체결 감지 | Spring WebSocket 클라이언트 |
| 주기 작업, 시간 청산 | Spring 스케줄러 |
| 매매 기록 | CSV 파일 |
| 백테스트, 기록 분석 | Python, pandas |

봇과 분석 코드는 CSV 파일로만 연결되며, 서로의 코드에 의존하지 않습니다.

## 시작하기

### 준비물

- Java 21
- 토스증권 Open API 키 (WTS 설정에서 발급)
- 허용 IP 등록 (봇을 실행할 PC의 공인 IP를 토스 WTS 설정에 등록해야 함, 안 하면 403 에러 발생)

### 환경변수 설정

프로젝트 루트에 `.env` 파일을 만들고 `.env.example`을 참고해 값을 채웁니다. 이 파일은 git에 올라가지 않습니다.

```
TOSS_API_KEY=발급받은 키
TOSS_API_SECRET=발급받은 시크릿
```

선택 항목: 알림을 받으려면 `DAMDAM_DISCORD_WEBHOOK_URL`에 디스코드 웹훅 주소를 넣습니다 (`https://discord.com/api/webhooks/`로 시작하는 주소만 허용). 이 값은 비밀값이라 코드, 로그, 문서에 쓰지 않습니다.

### 조회 스크립트 실행 (한 번 실행하고 끝)

```
cd bot
./gradlew bootRun --args='--spring.profiles.active=query'
```

계좌, 보유 종목, 시간 청산 알림을 한 번씩 조회하고 종료합니다.

### 체결 감지 봇 실행 (계속 떠 있음)

```
cd bot
./scripts/start-listen.ps1   # 백그라운드로 시작
./scripts/stop-listen.ps1    # 종료
```

웹소켓 연결을 유지하면서 체결을 실시간으로 감지하고, 평일 장 시작 직후 시간 청산 기준을 확인합니다. 전용 프로필(`query`, `listen`, `paper-probe` 등)이 아닌 기본 실행이나 테스트에서는 실제 API를 호출하지 않습니다.

장중에 계속 켜져 있어야 해서, 집 PC 대신 상시 실행 서버(오라클 클라우드)에서 systemd로 등록해 돌리는 것을 권장합니다. 배포 절차는 [docs/deploy.md](docs/deploy.md) 참고.

### 실측 조회 러너 (3단계 확인용, 조회만 하고 종료)

```
cd bot
./gradlew bootRun --args='--spring.profiles.active=paper-probe'
./gradlew bootRun --args='--spring.profiles.active=paper-probe --repeat-minutes=10 --repeat-count=16'
```

Windows PowerShell에서는 `./gradlew` 대신 `.\gradlew.bat`을 씁니다 (위 조회 스크립트 실행도 같습니다). 두 번째처럼 반복 옵션을 주면 한 번 띄워 두는 것만으로 일정 간격으로 조회를 반복하고, 두 번째 회차부터 직전 회차와 달라진 값을 `[변화]`로 보여줍니다. 값이 언제부터 안 바뀌는지가 곧 확정 시각입니다. 종목 코드를 뒤에 붙이면 그 종목을 표본으로 씁니다. 결과는 콘솔과 `records/probe/paper-probe.log`(git 제외)에 남습니다. 조회 전용이며 주문은 하지 않습니다.

## 운영: 봇을 멈추는 방법

| 방법 | 효과 |
| --- | --- |
| `bot/data/STOP` 파일 만들기 | 자동 매도와 OCO 등록/수정을 즉시 멈춤. 재시작 불필요, 파일을 지우면 재개. 멈추는 순간 알림 |
| `./scripts/stop-listen.ps1` | 봇을 정상 종료(종료 알림 발송). 15초 안에 안 끝나면 강제 종료 |

**주의: 이미 등록된 OCO 조건주문은 봇을 멈춰도 토스 서버에서 계속 동작합니다.** 정지 파일이나 봇 종료는 새 주문과 OCO 등록/수정만 막을 뿐, 서버에 걸려 있는 익절/손절은 그대로 발동될 수 있습니다 (국내는 KRX 정규장에서만, 해외는 거래 가능한 모든 세션에서 발동, 공식 문서 기준). 서버의 OCO까지 없애려면 토스증권 앱이나 WTS에서 직접 취소해야 합니다. 정지 중에는 시간 청산도 멈추므로 물림 방지 장치도 함께 멈춘다는 점을 기억하세요.

## 보안

- API 키, 시크릿, 토큰, 계좌 정보는 코드나 문서에 직접 쓰지 않고 `.env` 파일에서만 읽습니다
- 발급받은 토큰은 `bot/data/token.json`에 저장되며, `.env`와 동일한 수준으로 git과 접근 권한에서 제외됩니다
- 자동 매도(시간 청산)는 기본값이 **모의 실행**입니다. `.env`에 `DAMDAM_LIVE_ORDERS=true`를 직접 추가해야만 실제 주문이 나갑니다
- 실전 전환 후에도 안전장치가 적용됩니다: 1회 주문 금액 한도(국내 10만원, 해외 $71), 하루 최대 자동 매도 10회, 연속 손실 3회 시 자동 매도 정지
- 자세한 보안 규칙은 [CLAUDE.md](CLAUDE.md)를 참고하세요
