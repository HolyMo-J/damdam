# damdam 점검 절차

코드가 돌아가는지가 아니라 **전제가 맞는지**를 점검한다. 문법, 테스트 통과는 이 절차의 대상이 아니다.

## 언제 쓰나
- 데이터를 수집하거나 가공하는 코드를 새로 만들 때
- 백테스트 파라미터를 정하거나 결과를 사용자에게 보고할 때
- 주문, 청산, 안전장치처럼 돈이 움직이는 코드를 만들거나 바꿀 때
- 수치가 예상과 다르거나 이상한데 그냥 넘어가려 할 때

## 1. 실행 전에 세 문장을 적는다
1. 목적: 이 작업의 결과를 어디에 쓰는가
2. 암묵적 가정: 당연하다고 생각하고 확인하지 않은 것 (예: "많이 받아두면 좋다", "이 값은 원래 이렇다")
3. 틀릴 수 있는 이유: 이 가정이 깨지면 결과가 어떻게 무의미해지는가

세 번째 문장을 못 쓰겠으면 아직 이해하지 못한 것이다. 그 상태로 진행하지 않는다.

## 2. 프로젝트 특화 점검 항목

### 데이터
- 범위: 기간이 목적에 맞는가. 시장 구조가 바뀐 시점 이전 데이터가 섞이지 않는가 (예: 2015-06-15 가격제한폭 ±15%에서 ±30%로 확대, 그 전에는 토요일 장도 있음)
- 한도에 걸린 값: 결과가 우리가 정한 상한과 정확히 같지 않은가 (예: 봉 수가 정확히 10000이면 데이터 한계가 아니라 수집기 상한에 잘린 것)
- 생존 편향: 종목군이 "오늘 기준"으로 뽑혀 과거 실패 사례가 빠지지 않았는가
- 조정: 액면분할, 증자, 감자가 반영됐는가. 조정되지 않은 사건은 가격만으로 못 걸러낸다는 한계를 아는가
- 결측과 거래정지: 거래량 0인 날, 주말/휴일 봉, 중복 날짜가 있는가
- 단위와 통화: 원, 달러, 주 단위, 퍼센트 대 비율을 섞지 않았는가

### 백테스트
- 룩어헤드: 신호일에 알 수 없는 정보(당일 종가 이후, 미래 평균)를 쓰지 않는가
- 봉인: 최종 검증 구간을 코드가 로드하지 않는가. 결과를 본 뒤 기준을 바꾸지 않았는가
- 시도 횟수: 몇 번 시도했는지 기록하는가. 좋은 결과는 시도가 많을수록 우연일 가능성이 커진다
- 비용: 수수료와 매도세를 반영했는가
- 표본: 건수가 충분한가. 특정 종목이나 시기에 쏠리지 않았는가
- 결과가 좋을수록 먼저 의심한다. 좋은 이유를 설명하지 못하면 버그나 편향부터 찾는다

### 돈이 움직이는 코드
- CLAUDE.md 보안 규칙을 지키는가 (실제 주문 호출 금지, 기본값은 주문 안 보내는 모드, 금액과 횟수 한도)
- 봇이 재시작되거나 연결이 끊겨도 상태가 안전한가
- 실패했을 때 조용히 지나가지 않고 알리는가

### 문서와 주장
- 확인하지 않은 것을 사실처럼 쓰지 않았는가. 모르면 "확인 못 함"이라고 쓴다
- 이전 세션이나 문서에 적힌 수치도 그대로 믿지 않고 다시 볼 가치가 있는가

## 3. 만든 것은 수치를 읽고 나서 다음으로 넘어간다
데이터나 결과를 만들었으면 다음을 먼저 출력해서 직접 읽는다.
- 날짜 범위(처음과 끝), 건수, 최솟값과 최댓값, 종목별 편차
- 정확히 둥근 숫자(10000, 100 등)나 모든 종목이 똑같은 값

## 4. 놀라운 값을 발견했을 때
"놀랍다"고 느낀 순간이 신호다. 순서는 항상 같다.
1. 원인을 묻는다 (데이터 한계인가, 우리 코드의 한도인가, 실제 현상인가)
2. 원인을 확인하기 전에는 문서에 사실로 쓰지 않는다
3. 확인한 뒤에 원인과 함께 기록한다

## 5. 독립 검토가 필요하면
데이터 수집/가공 설계, 백테스트 파라미터와 결과 보고, 주문 관련 코드는 `damdam-reviewer` 에이전트에게 검토를 맡긴다. 이 에이전트는 이 대화를 보지 못하므로 프롬프트에 다음을 담는다.
- 목적과 지금까지 정한 것
- 검토할 파일 경로나 diff 범위, 확인한 수치와 출력 결과
- 내가 세운 가정 (세 문장 중 두 번째와 세 번째)
- 원하는 결론을 미리 말하지 않는다. 반박해 달라고 요청한다

에이전트가 지적한 것은 그대로 따르지 않고 실제 코드와 데이터로 검증한 뒤 판단한다 (CLAUDE.md 작업 규칙).

## 사고 사례: 1988년 데이터 (2026-09-21)
수집기에 시작일 제한 없이 상한(1만 봉)만 두어서 30종목 중 다수가 1988년부터 받아졌다. 이전 세션에서 "1988년부터인 종목이 있다"를 데이터 특성으로 기록했지만, 실제로는 수집기 상한에 잘린 값이었고 시장 구조도 지금과 달랐다. 세 문장의 두 번째("많이 받아두면 좋다")를 적었다면, 그리고 봉 수가 정확히 10000인 것을 이상하게 봤다면 막을 수 있었다.
