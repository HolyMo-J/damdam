# 리뷰 작업 목록

완료 표시 방법: 항목 번호 뒤에 `[완료 YYYY-MM-DD]` 태그를 붙인다. 예: `1. [완료 2026-09-28] 자금 단계와...`
새 세션에서는 이 파일을 읽고 완료 표시가 없는 첫 항목부터 이어간다.

---

아래 D묶음은 다른 Claude 대화에서 이 저장소의 docs 폴더와 CLAUDE.md를 읽고 사용자와 논의해서 정한 내용이다. 그 Claude는 코드 실행이나 실제 API 호출을 하지 못했다. 이전 A/B/C묶음(외부 리뷰 15개 항목)은 모두 처리되어 2026-09-23에 이 파일이 삭제됐었고, 이번에 D묶음만 새로 담아 다시 만들었다.

시키는 대로 그대로 고치지 말고 항목마다 이렇게 진행한다.
- 먼저 실제 문서와 코드, 공식 문서로 내용이 맞는지 직접 확인하고 근거를 보여준다.
- 틀렸거나 기존 문서와 충돌하면 고치지 말고 이유를 말한다.
- 파일을 만들거나 수정하기 전에 방향을 사용자에게 먼저 확인하고, 선택지를 낼 때는 권장하는 쪽을 같이 적는다.
- 실제 돈이 움직이는 코드는 보수적으로 판단하고, 확신이 없으면 고치지 말고 물어본다.
- 커밋 메시지는 한글로 쓴다. 추측으로 채우지 말고 모르는 건 공식 문서를 확인하거나 사용자에게 물어본다.

진행 방식
- 1번부터 7번은 문서 작업이라 한 세션에서 이어서 해도 된다. 8번은 코드 변경이라 단독 세션으로 한다.
- 9번은 설계안만 만들고 구현은 하지 않는다. 구현은 오라클 서버 배포가 끝난 뒤 사용자가 따로 시킨다.
- 진행 중 새로 발견한 문제는 docs/todo.md의 나중에 항목에 한 줄로만 기록한다. 돈이 잘못 움직이거나 손절 보호가 사라질 수 있는 문제는 바로 알린다.
- 항목 하나가 끝나면 `finish-task` 스킬로 마무리한다 (테스트, 커밋 승인, 이 파일의 완료 표시, todo/done 갱신). 예전에 있던 전용 review-done 스킬은 참조 대상(이 파일)이 없어져 2026-09-25에 삭제됐고, 지금은 사용자 전역 CLAUDE.md의 `finish-task`가 그 역할을 한다.

용어
- 한 주간은 주식 1주가 아니라 월요일부터 금요일까지의 1주일이다.
- 자금은 토스 계좌 전체 잔고가 아니라 담담에 쓰기로 정한 금액이다. 계좌에 다른 보유 종목이 있어서 잔고를 읽어 쓰면 안 되고, 설정값으로 직접 넣는 방식이어야 한다.

- 10만원 단계: 10만원 전체를 실험비로 본다. 종목당 1퍼센트 한도는 적용하지 않고 여러 종목으로 나눠 사는 것을 허용한다. 대신 한 주간의 실현 손실 합계가 1만원(자금의 10퍼센트)을 넘으면 그 주간은 새 매수를 멈춘다.
- 100만원 이상 단계: 1회 손실 한도는 자금의 1퍼센트. 매수 금액은 자금 x 1퍼센트 / 손절폭 퍼센트로 정한다. 손절폭은 ATR 1배를 매수가로 나눈 값. 한 주간의 실현 손실이 자금의 3퍼센트를 넘으면 그 주간은 새 매수를 멈춘다.
- 주간 손실 한도는 매도가 아니라 새 매수를 멈추는 장치다. 실전에서는 매수를 사용자가 직접 하므로 봇은 한도를 넘으면 디스코드로 이번 주 매수 중단 알림만 보낸다. 가상매매에서는 봇이 새 가상 매수를 실제로 멈춘다.
- 다음 단계로 증액하는 조건: 현재 단계에서 거래 50건 이상, 비용 반영 거래당 평균 손익이 플러스, 주간 정지 없이 4주 연속. 승률만으로 판단하지 않는다.
