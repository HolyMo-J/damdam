# 리뷰 작업 목록

완료 표시 방법: 항목 번호 뒤에 `[완료 YYYY-MM-DD]` 태그를 붙인다. 예: `4. [완료 2026-09-20] ATR 계산에서...`
새 세션에서는 이 파일을 읽고 완료 표시가 없는 첫 항목부터 이어간다.

---

아래 수정사항 목록은 다른 Claude 대화에서 이 저장소를 리뷰하고 작성한 것이야. 그 Claude는 저장소를 읽기만 했고 빌드나 테스트, 실제 API 호출은 하지 못했어. 그래서 틀린 내용이 섞여 있을 수 있어.

시키는 대로 그대로 고치지 말고 항목마다 이렇게 진행해줘.
- 먼저 실제 코드와 공식 문서로 지적이 맞는지 직접 확인하고 근거를 보여줘.
- 지적이 틀렸거나 과하다고 판단되면 고치지 말고 이유를 말해줘.
- 고치기로 한 항목은 파일을 만들거나 수정하기 전에 방향을 나에게 먼저 확인하고, 선택지를 낼 때는 권장하는 쪽을 같이 적어줘.
- 실제 돈이 움직이는 코드는 보수적으로 판단하고, 확신이 없으면 고치지 말고 물어봐줘.
- 커밋 메시지는 한글로 써줘. 추측으로 채우지 말고 모르는 건 공식 문서를 확인하거나 나에게 물어봐줘.

진행 방식은 이래.
- 가장 먼저 이 목록 원문 전체를 docs/review-tasks.md에 저장하는 안을 나에게 보여줘. 승인하면 저장해줘. 항목마다 /clear로 세션을 나눌 것이라 이 프롬프트가 사라지기 때문이야. 파일 맨 위에는 완료 표시 방법을 적어줘. docs/todo.md에는 이 파일을 가리키는 한 줄만 넣어줘.
- 그 다음 A묶음을 번호 순서대로, 한 세션에 항목 하나씩 진행해줘. 항목 하나가 끝나면 멈추고 결과를 요약하고, 내가 /clear 하고 다음 항목을 시킬 수 있게 다음 항목 번호를 알려줘. 새 세션에서는 docs/review-tasks.md를 읽고 완료 표시가 없는 첫 항목부터 이어가줘.
- A묶음이 모두 끝나면 멈추고 요약해줘. B묶음은 내가 시킬 때만 진행해줘.
- 진행 중 새로 발견한 문제는 바로 작업하지 말고 docs/todo.md의 나중에 항목에 한 줄로만 기록해줘. 다만 돈이 잘못 움직일 수 있거나 손절 보호가 사라질 수 있는 문제는 나에게 바로 알려줘.
