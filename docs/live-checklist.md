# 실전 전환 체크리스트

## 범위
이 체크리스트는 1단계 봇의 청산 자동화(시간 청산 + ATR OCO)를 실전으로 전환할 때(`.env`에 `DAMDAM_LIVE_ORDERS=true` 추가) 확인할 목록이다. 매수는 여전히 사용자가 직접 하고, 봇은 청산만 규칙대로 자동 실행한다(1단계 정의, CLAUDE.md 참고).

docs/strategy.md의 "판단 기준"(실전 전환 기준 4개: 거래 건수, 비용 반영 기대값, 최대 손실폭, 코스피200/30종목 동일가중 대비 비교)은 2단계에서 검증한 "과열 급락 반등" 전략으로 봇이 매수까지 스스로 하게 될 때(4단계 소액 실전)의 별도 게이트다. 2단계는 지금 잠정 보류 상태이고 이 체크리스트와는 무관하다.

## 실전 전환 직전에 확인할 것
- `bot/data/auto_sell_guard.json`을 직접 삭제해서 초기화한다. 예전 모의 실행 기록이 남아 있으면 실전 전환 첫날부터 연속 손실 정지 상태로 시작할 수 있다
- STOP 파일 실제 테스트: `bot/data/STOP` 파일을 만들어서 자동 매도와 OCO 등록/수정이 실제로 멈추는지, 알림이 오는지 확인한다
- 디스코드 알림 실제 수신 테스트: 시간 청산의 각 알림 경로(매수 체결일 미확인, 관리 범위 밖, 주문 한도 초과, 자동 매도 실패, 매도 접수/체결), 403(허용 IP 미등록) 알림을 최소 1회씩 실제로 받아본다
- 재연결(재동기화) 검증: 봇을 띄운 채 네트워크를 잠깐 끊었다 붙여서 로그의 `주문 재동기화 완료`를 확인한다 (아직 실제 재연결 상황으로 확인한 적 없음)
- 첫 국내 OCO 등록 로그 확인: 호가 단위 불일치로 거부돼 지정가를 보정하는 로그(`호가 단위 불일치로 거부돼 지정가를 보정해`)가 실제로 나오는지, 보정 방향(익절/손절 모두 아래쪽)이 맞는지 확인한다. 감시가(`first.triggerPrice`)도 호가 단위 검증 대상이면 보정 없이 실패 알림만 나가는데, 그 경우도 여기서 함께 확인한다 (docs/troubleshooting.md 9, 14번 참고)

## 모의 관찰 기간 (사전 등록, 2026-09-23, 결과를 보기 전에 고정)
- 기간: 최소 2주(10영업일) 연속 모의 실행(`damdam.orders.live-mode=false`, 기본값 그대로)
- 통과 조건 (모두 충족해야 함)
  - 시간 청산 트리거 로그 최소 1건 이상 (모의라 실제 매도는 없지만 판정 로직이 실제로 발동하는지 확인)
  - OCO 등록/수정 성공 로그 최소 1건 이상
  - STOP 파일 테스트 1회 이상 성공
  - 디스코드 알림 종류별 최소 1회씩 수신 확인 (위 "실전 전환 직전에 확인할 것"과 겹치면 그걸로 충족한 것으로 본다)
  - 웹소켓 재연결 테스트 1회 이상 성공
  - 원인 불명 예외나 크래시 0건
- 하나라도 실패하면 원인을 고친 뒤 관찰 기간을 처음부터 다시 센다. 통과하지 못한 채로 기준을 낮추지 않는다

## 첫 실전 방침
- 1주 단위 소액으로 시작한다
- 1회 주문 금액 한도(`damdam.orders.max-amount-krw`, 기본 10만원)는 폭주 방지용으로 유지하고, 실전 첫 단계에서는 매수 금액 자체를 이 한도 안으로 맞춘다 (docs/strategy.md 참고). 한도를 넘는 포지션은 시간 청산이 계속 건너뛰어진다
