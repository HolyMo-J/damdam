## 서버 이전 고민 (지금은 보류, 실전 전환이 가까워지거나 필요해질 때 재검토)
- 지금은 집 PC에서 `start-listen.ps1`로 띄운 프로세스라 PC를 끄면 봇도 꺼진다. 봇이 꺼진 동안은 체결 감지, 시간 청산, OCO 자동 등록이 멈춘다. 이미 토스 서버에 등록된 OCO는 계속 동작하고(실전 전환 후), 봇을 다시 켜면 재동기화가 최근 7일 안의 놓친 체결을 채운다
- 2026-09-20 조사 결과 (다시 조사할 때 여기부터 이어간다)
  - 오라클 클라우드 Always Free: 공인 IP(Reserved Public IP)는 완전 무료라 고정 IP 조건은 맞음. 사양은 2026-06-15에 4 OCPU/24GB에서 2 OCPU/12GB로 축소됐고 신규 계정은 UI상 더 낮게 제한될 수 있음. 가장 큰 위험은 유휴 인스턴스 자동 회수 정책(7일간 CPU/네트워크 사용률 20% 미만이면 회수 가능)인데, 우리 봇은 대부분 조용히 대기하는 패턴이라 걸릴 가능성이 있음. 리전에 따라 신규 인스턴스 생성 자체가 재고 부족으로 실패하는 경우도 흔함. 실제로 되는지는 가입해서 만들어봐야 확인 가능
  - GCP e2-micro: Always Free지만 리전이 미국 3곳(us-west1/central1/east1)뿐, 사양이 더 작음(공유 vCPU 1개, RAM 1GB), 월 무료 트래픽 1GB로 부족할 수 있음. 2024년부터 공인 IP 자체에 시간당 과금이 붙기 시작해서 완전 무료가 아닐 가능성이 큼 (정확한 무료 한도는 확인 못 함)
  - AWS, Azure: 상시 무료 VM이 아님. AWS는 2025-07-15 이후 신규 가입 시 12개월 무료 대신 6개월 $200 크레딧으로 바뀜, Azure는 처음부터 12개월만 무료
  - 유료 최저가 비교: 카페24 리눅스 VPS 월 9,000원(+최초 설치비 22,000원, 1GB RAM/30GB/300GB 트래픽), 가비아는 공공기관 전용 페이지 기준 월 25,000원대(일반 상품 정확한 가격은 확인 못 함), Vultr 서울 $5~6/월, 네이버클라우드(NCP)는 서버비 1년 무료지만 공인 IP는 처음부터 별도 과금이고 1년 뒤 유료 전환
  - GCP/AWS 계정을 무료 체험 기간마다 새로 만들어 돌려쓰는 방안도 논의했으나, 약관 위반으로 계정이 예고 없이 정지될 위험과 계정을 바꿀 때마다 토스 허용 IP를 재등록해야 하는 운영 부담 때문에 보류하기로 함
  - 노트북을 상시 충전 상태로 돌리는 방안은 검토 결과 기각: 지금 집 PC와 같은 집, 같은 회선에 있어 정전/인터넷 장애 위험이 그대로고, 뚜껑 닫힘 절전 설정과 배터리 열화 문제까지 추가됨. 서버 이전의 대안이 아니라 지금 상태 유지에 가까움
  - 결론: 오라클이 가장 유력한 후보지만 불확실성(회수 정책, 리전별 재고)이 남아 있고 유료 대안도 뚜렷한 이점이 없어서, **실제로 이전이 필요해지는 시점(예: 실전 전환 준비)에 다시 고민하기로 하고 지금은 보류**
- 결정 전에는 집 PC에서 계속 운영한다

## 확인 필요
- 이미 있는 `bot/data/token.json`의 권한은 다음 토큰 발급 때 자동으로 고쳐짐. 지금 바로 고치려면 PowerShell에서 직접 실행: `icacls bot\data\token.json /inheritance:r /grant:r "$($env:USERNAME):F"` (결과는 `icacls bot\data\token.json`으로 확인, 소유자 항목 하나만 남아야 함)
- 국내 OCO 호가 단위 자동 보정은 문서 예시 응답 기준으로 구현했고 실제 국내 종목 응답은 확인하지 못함. 실전 전환 후 첫 국내 OCO 등록 로그(`호가 단위 불일치로 거부돼 지정가를 보정해`)를 확인할 것. 특히 감시가(triggerPrice)도 호가 단위를 검증하는지는 문서에 없음. 그 경우 필드가 `first.triggerPrice`로 오고 보정 없이 실패 알림이 나감
- 재동기화는 실제 재연결 상황(네트워크를 끊었다 붙이기)으로는 아직 확인하지 못함. 봇을 띄운 채 네트워크를 잠깐 끊고 로그의 `주문 재동기화 완료`를 확인할 것
- GitHub Actions는 push 뒤 저장소의 Actions 탭에서 실제로 통과하는지 확인할 것 (로컬에서는 실행 불가)
- 실전 전환(.env에 DAMDAM_LIVE_ORDERS=true 추가) 전에 `bot/data/auto_sell_guard.json`을 직접 삭제해서 초기화할 것. 예전 모의 실행 기록이 남아 있을 수 있음
- 해외(US) 수수료율 적용 종료일이 2026-09-19로 도래함. `query` 프로필로 다시 조회해서 요율이 바뀌었는지 확인 필요
- 저장소는 공개. 종목 코드는 문서에서 일반화했지만 커밋 이력에는 남아 있음 (토큰, 키, 웹훅 주소, 계좌번호는 이력에 없음을 확인했고, 이력 정리는 하지 않기로 함)
- 실전 전환 기준 4개(거래 건수, 비용 반영 기대값, 최대 손실폭, 비교 통과 조건)는 2026-09-19에 모두 확정해 docs/strategy.md에 기록함. 백테스트 결과를 본 뒤에는 바꾸지 않는다
- 시간 청산 매도가 접수된 뒤 체결 전에 봇이 재시작되면, 그 1건은 연속 손실 판정에서 빠질 수 있음(메모리 기반 상관관계라 재시작 시 유실). 드문 경우로 보고 감수하기로 함, 문제가 반복되면 재검토

## 나중에 (실전 전환을 막지 않는 것)
- 판단 기준의 "손절폭(1R) 대비 기대값도 0보다 커야 한다" 조건이 confirm.py와 portfolio.py 어디에도 검증되지 않는다 (2026-09-23, damdam-reviewer 지적). 판단 기준 문서 전체를 다시 볼 때 점검한다
- OcoPeriodicCheckService가 장 마감 시간에도 60초마다 holdings 조회 1회 + 관리 종목별 조건주문 조회를 계속 보낸다 (시간 가드 없음). 관리 종목이 소수라 호출 제한에는 여유가 있어 당장 문제는 아니지만, 장 운영시간 가드를 추가할지 검토한다
- 백테스트는 시장 전체 급락일 진입 금지를 구현하지 않았다 (지수 데이터 없음). 30종목 동일가중 일수익률로 근사하는 필터는 결과를 보기 전에 임계값 하나로 고정할 수 있을 때만 넣는다
- 손절 체결 가정의 차이: 백테스트는 갭 하락 손절을 시가 체결로 계산하지만, 봇의 OCO 손절은 감시가 한 호가 아래 지정가라서 갭 하락 시 체결되지 않을 수 있다는 추정이 있다. 토스 공식 문서로 OCO 감시가/지정가 동작을 확인하고, 3단계 가상매매에서 갭 하락 케이스를 따로 기록하며, 백테스트에 미체결 시나리오 민감도를 추가할지 검토한다
- 봇 규칙과 백테스트 규칙 정렬: 봇의 AtrOcoPricing은 익절 ATR 1배 손절 ATR 1배인데, 백테스트 주 후보는 익절 5% 고정 손절 ATR 1.5배다. 3단계 가상매매를 시작하기 전에 봇의 계산을 맞춘다
- 해외 종목 ATR의 오늘 봉 제외: AtrService가 시스템 날짜와 캔들 날짜를 비교하는데, 해외 종목 캔들 날짜가 어느 시간대 기준인지 확인하고 진행 중인 봉이 섞이지 않는지 점검한다
